# Plan 28-01: Add Durable Setup-State Contract

## Goal

Persist onboarding as a durable workspace contract instead of a transient wizard session.

## Must Have

- setup state records deployment mode, deployment path, setup depth, selected steps, completed steps, blockers, and next action
- setup state lives under the shipped control-plane workspace
- onboarding and doctor can both use the same durable setup-state contract

## Expected Files

- `crates/cli/src/commands/onboard.rs`
- `crates/cli/src/commands/doctor.rs`

## Verification

- targeted onboarding and doctor tests for durable setup-state persistence and readiness interpretation
