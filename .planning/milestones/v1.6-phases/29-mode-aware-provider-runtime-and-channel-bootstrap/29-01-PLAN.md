# Plan 29-01: Persist Bootstrap Outcomes in Setup State

## Why

Phase 28 made setup resumable, but setup state still does not explain whether provider, runtime, or channel bootstrap actually worked. Phase 29 needs one durable place to record those outcomes so onboarding, repair, and handoff all read the same truth.

## Implementation

1. Extend `SetupState` with typed bootstrap outcome entries for setup surfaces such as provider, runtime, and channels.
2. Add helper functions that replace or update a bootstrap outcome without breaking the existing step-progress contract.
3. Add focused unit tests for the setup-state bootstrap outcome contract.

- `cargo test -p openrustclaw-cli onboard -- --nocapture`
