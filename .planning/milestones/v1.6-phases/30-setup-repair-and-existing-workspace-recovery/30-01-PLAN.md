# Plan 30-01: Add Explicit Repair Entry to Onboarding

## Why

Existing workspaces already expose some choices, but repair is still implicit. Operators need a direct recovery entry point that is separate from full reset and separate from a fresh path selection.

## Implementation

1. Add a dedicated repair option to the existing workspace onboarding menu.
2. Print a concrete repair plan before running targeted recovery steps.
3. Keep reset-with-backup visible as a separate destructive option.

## Verification

- `cargo test -p openrustclaw-cli onboard -- --nocapture`
