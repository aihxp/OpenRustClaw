# Requirements: OpenRustClaw

## Active Milestone: v1.19 Full Greenfield Conversion: Control Plane Route Families I

**Goal:** Continue the post-`18/18` greenfield program by shrinking the largest remaining control-plane hotspot in `start.rs`, beginning with config, diagnostics, channel registry, and read-heavy runtime or operator status route families.

**Current greenfield baseline:** The historical ranked seam ledger from `v1.13` through `v1.18` is complete at `18/18` and remains retired. The deeper follow-on conversion program is now defined in `.planning/codebase/GREENFIELD-FULL-CONVERSION.md`.

## Requirements

### GFC-21 Control config validation and mutation route family

The remaining control config route family in `crates/cli/src/commands/start.rs` must move behind a stable application service boundary so `/control/config`, `/control/config/validate`, and `/control/config/update` stop owning business orchestration inside the route hub.

**Status:** Planned for v1.19 Phase 81.

**Acceptance signals:**
- the control config route family is composed through `openrustclaw-app`
- `start.rs` becomes the HTTP adapter for config validation and config update flows instead of owning the business rules directly
- verification proves the shipped control config contract remains truthful

### GFC-22 Diagnostics and live operator event route family

The diagnostics summary and live diagnostics websocket or session orchestration in `crates/cli/src/commands/start.rs` must move behind a stable application boundary so diagnostics stop deepening the remaining control-plane hotspot.

**Status:** Planned for v1.19 Phase 82.

**Acceptance signals:**
- the diagnostics route family is composed through `openrustclaw-app`
- `start.rs` becomes the transport adapter for diagnostics and live event wiring instead of owning the orchestration directly
- verification proves the shipped diagnostics and live event contract remains truthful

### GFC-23 Channel registry account and binding lifecycle route family

Channel registry account, approval, activation, binding, and related lifecycle orchestration in `crates/cli/src/commands/start.rs` must move behind a stable application service boundary so registry lifecycle flows no longer live inside the same oversized route hub.

**Status:** Planned for v1.19 Phase 83.

**Acceptance signals:**
- channel registry account and binding lifecycle orchestration is composed through `openrustclaw-app`
- `start.rs` becomes the HTTP adapter for registry lifecycle flows instead of owning the business rules directly
- verification proves the shipped channel registry control contract remains truthful

### GFC-24 Runtime, voice, talk, and mobile status route family

The remaining read-heavy runtime, voice, talk, and mobile status handlers in `crates/cli/src/commands/start.rs` must move behind bounded application-owned summaries so the control plane stops composing those status contracts route-locally.

**Status:** Planned for v1.19 Phase 84.

**Acceptance signals:**
- runtime, voice, talk, and mobile status handlers compose through `openrustclaw-app`
- `start.rs` becomes the HTTP adapter for those status surfaces instead of owning the report composition directly
- verification proves the shipped runtime and operator status contract remains truthful
