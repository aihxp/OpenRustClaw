# Plan 23-02: Add Enable, Disable, And Kill-Switch Controls To The Shipped Admin Surface

## Goal

Make the enterprise admin surface capable of enabling, disabling, and kill-switching the full-autonomy lane through the new typed runtime routes.

## Must Have

- the shipped admin surface can submit enable, disable, and kill-switch actions
- those actions reuse the saved operator and approver headers already used for governance
- the UI exposes the relevant override budget inputs and note or reason fields without inventing a second admin workflow

## Expected Files

- `crates/cli/src/commands/control_ui.html`
- `crates/cli/src/commands/control_ui.rs`

## Verification

- dashboard coverage for the action controls and request wiring
