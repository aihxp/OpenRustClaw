## Scope

This milestone started the post-`v1.24` native-delivery program by defining the full legacy-delivery inventory, the app-port contract catalog, the successor delivery topology, and the shutdown rules needed to replace the legacy command tree with a clean native delivery layer.

## Milestone Requirements

- [x] **NDL-01**: The repo has a canonical inventory of every major remaining legacy delivery family plus a native target map for where that family should live after legacy retirement.
- [x] **NDL-02**: The roadmap defines the app-port contract families needed for CLI, control, MCP, runtime-worker, and repository-facing delivery.
- [x] **NDL-03**: The roadmap defines the successor native delivery crates or modules plus the bootstrap contract for the main binary, control server, MCP server, and runtime workers.
- [x] **NDL-04**: The native-delivery program has a truthful progress model, compatibility gates, and legacy shutdown rules before implementation milestones begin.

## Future Requirements

- Native control and MCP delivery layers must replace `start.rs` as the main control bootstrap surface.
- Native CLI dispatch must replace `main.rs` plus the legacy command tree as the primary product entrypoint path.
- Infrastructure adapters must own persistence, workspace, and external integration wiring that still lives in legacy command files today.
- Legacy command modules must be deleted, isolated, or reduced to bounded temporary shims before the program can claim complete legacy exit.

## Out of Scope

- Deleting the legacy command tree during `v1.25`
- Claiming the repo is fully off legacy before native delivery layers exist
- Big-bang rewrites that break shipped CLI, control, MCP, or worker entrypoints instead of replacing them incrementally
- Extending the retired `18/18` seam ledger or the completed `6/6` adapter-only roadmap with a new denominator
