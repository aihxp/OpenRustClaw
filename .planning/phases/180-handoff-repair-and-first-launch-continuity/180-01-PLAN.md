# Plan 180-01: Align Handoff and First Launch with the Selected Model Lane

## Goal

Make setup handoff, resume or repair prompts, and the first assistant launch stay aligned with the provider, access mode, and explicit primary model chosen during onboarding.

## Scope

- `crates/cli/src/commands/onboard.rs`
- `crates/app/src/setup_lifecycle.rs`
- `crates/cli/src/commands/chat.rs`

## Tasks

1. Distinguish onboarding model substeps in next-action text
- Generate truthful `next_action` guidance for the model step so resume or repair can distinguish provider selection, model selection, and provider verification repair.

2. Improve handoff detail with model-lane context
- Include the selected provider, access mode, and primary model in ready and provider-verification handoff detail text.

3. Make first assistant launch honor the selected model
- Resolve the selected onboarding model for the chosen provider and pass it explicitly into the first `chat::run(...)` launch path.

4. Verify continuity behavior
- Cover assistant-model preference, model-step next-action routing, handoff detail text, and persisted-model chat config loading with focused tests.

## Verification

- `cargo test -p openrustclaw-cli test_assistant_model_prefers_onboarding_state -- --nocapture`
- `cargo test -p openrustclaw-cli test_step_next_action_distinguishes_model_substeps -- --nocapture`
- `cargo test -p openrustclaw-cli load_chat_config_uses_persisted_model_when_no_override_is_supplied -- --nocapture`
- `cargo test -p openrustclaw-app setup_lifecycle -- --nocapture`
