# Plan 179-01: Add Explicit Primary Model Selection

## Goal

Let onboarding discover or scan models for the chosen provider, prompt for an explicit primary task model, persist that provider-model pair through the shared runtime switch lane, and record whether the choice came from live discovery, recommended fallback, or manual entry.

## Scope

- `crates/cli/src/commands/onboard.rs`
- `crates/app/src/setup_lifecycle.rs`
- `crates/app/src/setup_handoff.rs`
- `crates/cli/src/commands/inspect.rs`

## Tasks

1. Extend setup-state model metadata
- Add durable fields for selected primary model and model-source provenance across onboarding state, setup state, lifecycle state, inspect mapping, and handoff state.

2. Add onboarding-time model discovery and selection
- Discover live models for the chosen provider after provider verification succeeds.
- Offer a curated discovered shortlist when live discovery succeeds and a manual entry path when discovery is unavailable or empty.

3. Persist provider-model pair through the shared runtime lane
- Use the existing runtime switch service to persist the selected model alongside the chosen provider.
- Re-run provider verification against the selected model so onboarding closes on the final provider-model pair.

4. Verify state persistence and fallback behavior
- Cover shortlist construction, setup-state round-tripping, provider-path reset behavior, and runtime switch persistence with focused tests.
