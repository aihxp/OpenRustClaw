# Plan 178-01: Enrich Provider Verification Evidence

## Goal

Make onboarding provider verification truthful and durable by classifying live verification failures into operator-meaningful buckets and persisting that evidence through setup-state, repair, and handoff surfaces.

## Scope

- Reuse the existing runtime health scan in `crates/cli/src/commands/runtime.rs`
- Enrich onboarding bootstrap evidence in `crates/cli/src/commands/onboard.rs`
- Propagate richer verification data through:
  - `crates/app/src/setup_lifecycle.rs`
  - `crates/app/src/setup_handoff.rs`
  - `crates/cli/src/commands/inspect.rs`

## Tasks

1. Extend bootstrap evidence structures
- Add optional verification metadata to durable bootstrap outcomes so provider verification can record issue kind, verification stage, and a targeted next action without breaking existing serde defaults.

2. Upgrade provider verification classification
- Refactor `validate_provider_bootstrap(...)` to preserve runtime issue classifications from the health report and map them into onboarding-specific explanations for authentication, missing local runtime, model unavailability, billing or quota, rate limiting, or generic provider reachability failures.

3. Route repair and resume from richer evidence
- Update setup lifecycle and repair logic so provider verification failures remain attached to the model step but carry a truthful reason and targeted next action for resume or repair.

4. Cover the new verification lane with focused tests
- Add or update unit tests for outcome recording, provider verification classification, setup lifecycle repair routing, and inspect or handoff reporting.

## Verification

- `cargo test -p openrustclaw-cli onboarding -- --nocapture`
- `cargo test -p openrustclaw-cli setup_handoff_summary_reports_degraded_setup_state -- --nocapture`
- `cargo test -p openrustclaw-app setup_lifecycle -- --nocapture`
- `cargo test -p openrustclaw-app setup_handoff -- --nocapture`
