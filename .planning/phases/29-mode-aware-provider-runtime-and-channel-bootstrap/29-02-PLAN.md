# Plan 29-02: Validate Provider and Runtime Bootstrap During Onboarding

## Why

Writing an API key or switching the provider is not enough. Onboarding should use the shipped runtime health surface to decide whether the selected provider and control-plane/runtime lane are actually usable.

## Implementation

1. After provider setup, refresh runtime health and evaluate the selected provider's readiness.
2. After control-plane setup, record whether the selected runtime mode aligns with the chosen self-hosted deployment mode and whether the control registry exists.
3. Persist those outcomes into setup state and return warning or blocked results when bootstrap fails.

## Verification

- `cargo test -p openrustclaw-cli onboard -- --nocapture`
