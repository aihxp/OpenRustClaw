# Plan 31-02: Expose Setup Handoff in the Shipped Operator Surface

## Why

Operators need to review setup status after the wizard exits, especially when first start is blocked or degraded. That belongs in the shipped control surface, not only in terminal output.

## Implementation

1. Add a typed setup handoff summary in `inspect.rs`.
2. Expose it through a new control route in `start.rs`.
3. Render a `Setup Handoff` panel in Control UI with current status, next action, blockers, and bootstrap outcomes.

## Verification

- `cargo test -p openrustclaw-cli inspect -- --nocapture`
- `cargo test -p openrustclaw-cli control_ui -- --nocapture`
